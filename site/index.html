Eido

An interface that changes, inside limits you can see.

Eido is the design language of ML Weft. Weft studies models that change themselves within bounds you can check. Eido is the first place that idea is used in something people see every day: an interface that changes itself in response to the person using it, within bounds that person can see, check and undo.

The idea

What Eido is

Most pages treat every visitor the same, with a fixed theme and a fixed layout. Eido treats the interface as something that moves through a continuous space, and that moves because of what the reader does.

Every change has to stay inside limits the reader can see. The reader can check what happened and undo it. That is the same rule Weft applies to models.

This repository holds the parts that are generic, as small modules with tests. Weft's telemetry field is built on them.

Six principles

D1 to D6

Each card says where the principle is built. Demos on this page run the real modules. Where a principle lives in Weft or is still a design, the card says so and has no demo.

D1Implemented here

Style as a point in a continuous space

A style is a blend of a few presets. The weights of the blend are one point on a triangle. Drag the point and the style moves with it.

Aesthetic mixer · Simplex pad

D2Implemented here, in part

Analytical geometry and reading cadence

Each visual channel carries one quantity: area is value, position is rank. Text is drawn from a table of numbers, the same on the GPU and on a canvas. The field shader and the reading-cadence heuristic live in Weft.

Cell layout · Glyph font

D3Implemented in Weft

Compact, verified state

Everything the renderer needs fits in one 64-byte frame. Each packet carries a SHA-256 hash that the browser checks before any value is shown. A line without a hash counts as unverified.

No demo here. This runs in Weft's telemetry worker, not in this repository.

Weft runtime

D4Implemented in Weft

Surfaces that show strain

While a system's tension stays in its normal band, edges pulse gently. As it nears the hard limit, glow and grain change. Strain is visible without a modal alert.

No demo here. The field shader is in Weft.

Weft runtime

D5Design only

Places, not pages

People remember where something lives better than how far down a scroll bar it was. Eido would organise a large system into a few named rooms on a persistent canvas.

Not built. An earlier w3ft.org used six rooms; the current site is one page.

D6Implemented here

Text that answers how it is read

How someone reads is a signal the page can answer. Skim, and the text ripples, or condenses to its gist. Read, and it calms. This page runs the reading weave on you now.

Scroll quickly to watch it rise. Read slowly and it falls.

Components

Take what you need

Each module stands alone. Every page has an isolated demo, the files to copy, and a snippet that works when pasted.

D1src/aesthetic-mixer.js

Aesthetic mixer

Blends style presets with barycentric weights. Hue averages on the circle.
D1src/simplex-pad.js

Simplex pad

A triangle control. The point you drag is the weight vector.
D2src/cell-layout.js

Cell layout

Cell area follows value. Golden-angle packing fitted to any region.
D2src/glyph-font.js

Glyph font

A 5×7 bitmask font, two 32-bit words per glyph, the same table for GPU and Canvas.
D6src/reading-weave.js

Reading weave

Text ripples when you skim. Reading calms it.
D6src/condense.js

Condensing prose

An article condenses, level by level, as you skim.
In practice
